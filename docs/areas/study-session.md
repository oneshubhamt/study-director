# Study session

Today's study session (the Active Session) and its timer: what is stored, which device runs it, and how it moves between devices. Timer sounds and reminders are in [notifications.md](notifications.md).

## The Active Session

The Active Session is portable across devices and backups. It carries the current session/schedule/review state required to resume work, and the installation running it (`runningOn`, ActiveSession v10; an older session belongs to the installation that converts it). A restored running or paused timer is rehydrated into the timer runtime only on the installation it names, and the Execute controls are then derived from that restored runtime. Any other installation shows the session as running on another device and runs it only after Continue Here (below).

The Plan working draft and the applied Active Session schedule are separate state. Restoring or continuing a session applies the session's canonical schedule directly; it never writes that schedule through Plan-draft persistence and never enters Plan editing. Any local Plan draft remains exactly as authored. After a handoff the board stays in the applied/live state until the person explicitly chooses to edit, at which point the preserved draft is available.

**Plan board and save contract.** The board label and styling describe the content actually rendered: when an applied schedule exists and editing is closed, it stays LIVE even if the independent working draft is ready, incomplete or invalid. The Edit Draft control also identifies a separately authored invalid or empty draft instead of implying that it edits the live Plan. Explicit editing (or having no applied schedule) shows the draft's own state and validation. A silent preview during startup, restoration, import, reset or ownership change never replaces session feedback with an unrelated draft error. Cancel closes editing without replacing the draft; any queued preview is cancelled. User-initiated Apply/Done waits for one successful strict IndexedDB Plan-draft write before changing the applied schedule; a failed save or an intervening edit stops application without losing the previous live schedule. An unchanged live-plan reapply does not duplicate that write. Reapplying an already-canonical Active Session is deliberately synchronous, writes no working draft, and preserves its existing content.

**Authoring and Cancel lifecycle.** Plan Composer text, not delayed or previously rendered row memory, is the authority for Done. Confirm parses and renders that exact current text, rejects incomplete/invalid content without rewriting it, and strictly saves it once before any applied-schedule transition. The 220 ms preview only reads the latest text *when it fires*, and structured row edits cancel it; no cached preview may overwrite newer edits. Any pending Done or replacement/break confirmation is conditional on the same editor epoch: Cancel, a fresh edit or a reset invalidates it. Cancel closes editing immediately and leaves the applied session intact, but explicitly reports the draft as *saving* until one strict IndexedDB write has completed; it reports saved only after that commit, or displays an actionable failure without claiming durability. Opening and cancelling an **untouched** displayed default template does not convert canonical `draft:null` into an authored draft; deliberately typing the same default does count as authorship. The existing serialized Plan writer and the independent draft/session separation remain authoritative; no additional persisted format or background subsystem is introduced. Real-browser and device acceptance remains a separate gate.

**Previous-day recovery and evidence.** A canonical previous-day Active Session is historical work regardless of whether it was active or suspended, and regardless of the device named by `runningOn`. Startup, ownership rehydration, the former Continue Here action, and backup/rollback restoration route it to a **Previous Day Needs Review** state, not a runnable or transferable timer. A covering canonical Saved Day, combined with that session's own durable acknowledgement, retires its redundant local recovery copy before the Review prompt. While historical Review remains open, the normal clock and timer-engine rollover adapter must not auto-save or close that previous day: the user decides when to save it. Otherwise the person may recover it into Review without starting the timer, leave it stored with a persistent **Review Previous Day** action, or deliberately discard a local-owned copy through the existing exclusive mutation owner and strict canonical deletion verification. A remotely owned historical copy is never offered destructive local discard. A changed canonical session invalidates an outstanding Review choice rather than applying a stale decision.

**Reminder reconciliation.** A Save Today warning captures only a strictly committed same-date session snapshot whose content revision matches the visible runtime. Following a canonical Saved Day write or completed backup reconciliation, the warning is checked afresh against the actual canonical Day, canonical session acknowledgement (if still present), and any retained uncovered divergent session. After verified coverage, it may be dismissed **without** changing `savedRevision` or falsely acknowledging another session; its old inline Review instruction is cleared only if that instruction has not been replaced by newer status feedback; missing evidence, local rescue-only current session, an unacknowledged current session, or failed storage reads retain the warning. The evidence is volatile in-memory notice context, not another stored state or merge authority.

**Safely extended evidence.** The shared `DailyRecordCodec.savedDayCoversSessionEvidence` predicate allows non-decreasing measured progress and exact-prefix pause events. A later focus end is additionally accepted only when the original start is unchanged, the finish is strictly later and actual recorded focus duration has increased. Partial Practice Pacer runs may continue only with the same task/target/plan metadata and an exact unit-duration prefix; runs are matched one-to-one, reserving exact complete-run matches before assigning partial continuations. Edited or missing starts, shorter duration, non-prefix practice, a changed target, unrecorded results, unacknowledged session work and unverified saved data remain conflicts requiring recovery or review. No global timestamps or cross-device numeric revision comparisons substitute for semantic proof.

**Unfinished Practice Pacer evidence.** Save Today and date rollover finish a running or paused Practice Pacer attempt into a partial Saved Day run before saving. The Saved Day coverage predicate must account for that preceding active attempt as well as earlier finished runs: each saved run may cover at most one observed attempt; task, target/plan identity and already completed units must agree, and a previously recorded current unit must not shrink. A running attempt includes the elapsed time observable between its anchor and the canonical snapshot timestamp, capped at the live pacer's 24-hour per-unit ceiling before comparison. Missing or contradictory clock evidence fails closed. A setup with no completed units and no elapsed study time is not saved-study evidence. The coverage check never changes the underlying Saved Day, session or revision acknowledgment.

## Across devices

Decisions (owner, 2026-10-18):

- The session names the device running it; only that device runs the timer. Another device shows "Running on another device" and edits notes and everything else freely; notes from it reach the running device without stopping its session.
- Suspend hands the session over: it uploads at once and the other device offers Continue here.
- Continue Here and Restore Session sit in Execute's status card and in the session strip above the Plan board, in one order: next step, Suspend, Finish, Reset last. Controls that cannot act are hidden, not disabled. Continue Here on a device whose copy still runs elsewhere asks first; the device taken over from stops at its next sync and keeps its unsynced progress for review.
- "Needs review" opens during a running session and leaves the session as it is.

How Continue Here shows its steps and errors: [status-indicator.md](status-indicator.md#continue-here).

**How sync treats it.** The session names the device running it (`runningOn`, the installation id), and only that device runs its timer. Another device keeps a copy it never runs and shows "Running on another device"; notes, Saved Days and everything else work there as usual. Ordinary reconciliation still uses the exact canonical Active Session fingerprint stored in the shared reconciliation baseline. The lightweight Drive ownership claim is a separate control-plane fact: while its newest applicable epoch names this device, an older checkpoint naming the previous owner cannot hand execution back.

Ownership metadata and study content are deliberately different reconciliation domains. The Active Session codec defines a semantic content projection containing the date, applied schedule and study evidence while excluding `runningOn`, status, session/content/save revision counters and persistence timestamps. Continue Here binds its ownership claim to a SHA-256 fingerprint of exactly that semantic content. A pure ownership transition therefore creates no false content conflict. If the old owner later publishes study evidence that differs from the handoff boundary, sync can distinguish one-sided continuation from genuine two-sided divergence; genuine divergence is kept for review rather than discarded.

A Saved Day and an Active Session use related revision numbers, but those numbers are **not cross-device ancestry identifiers**. Save Today records the current session content revision in the Saved Day and, on that same session lineage, advances `ActiveSession.snapshot.savedRevision` before persisting the session again. On a later launch, a previous-day Active Session is retired quietly only when its own `savedRevision >= contentRevision` and the canonical Saved Day for that date exists. Sync does not infer that one device's Saved Day covers another device's session merely because their numeric counters compare. If the remote side has a newer Saved Day and no Active Session, that explicit end-of-session state outranks the ordinary running-session hold rule; any genuinely divergent local session content is kept for review before the stale recovery row is retired.

## Moving a session

Active Session content and ownership are separate. Continue Here first flushes the independent Plan draft, then reads the newest verified Drive head **without running general sync**: it verifies the head manifest/commit and opens only the repository object containing the Active Session. If the local and verified-shared semantic content fingerprints differ, Continue Here checks the current owner's preceding ownership claim. When this device still holds exactly the semantic content that claim recorded at the prior handoff boundary, the newer Drive Active Session is a proven one-sided continuation and is advanced locally before ownership moves—without touching Plans, notes or Saved Days. If that causal proof is absent, both sides diverged, or the newer session carries attachment dependencies, Continue Here stops and schedules ordinary sync so reconciliation remains lossless.

If the content matches, Continue Here acquires a new monotonic Drive ownership epoch through the protected **v4** claim (v3 remains readable for earlier handoffs). The claim contains opaque session/owner tokens plus a SHA-256 fingerprint of the exact semantic session content observed at handoff; no schedule, progress, device id or date is stored in plaintext. Under the publication lease, Drive's head is re-listed and must still be the exact verified checkpoint that was observed before the claim is written. Only after the claim is durably read back does this device strictly save and read back the new local owner session; only then may its timer run. A failed local commit writes a newer compensating ownership claim when that rollback can be verified. If compensation itself cannot be verified, the handoff fails closed and the timer does not start; reloading/retrying resolves the durable claim rather than pretending ownership is known.

The newest applicable ownership epoch remains authoritative until a later verified epoch supersedes or explicitly releases it; it does not expire by time. An open old owner checks the lightweight claim about every 15 seconds, flushes its latest progress, freezes only its runtime clock, and forces Drive catch-up; canonical progress remains untouched so ordinary reconciliation can keep any divergence for review. Older claim files are compacted best-effort after a successful full checkpoint. Suspend and plan-apply still publish urgently through the normal shared checkpoint path.

## When this device loses the session

When a verified lightweight Drive claim shows that this device no longer owns its running Active Session, Study Director stops its local execution loop immediately and preserves the frozen timer/practice evidence. The local draft must commit through strict canonical IndexedDB storage and pass a matching strict read-back before claim-triggered sync starts. Failure, null result and emergency local-only rescue are **not** declared canonical; the page retains a persistent safety warning and retries through its existing 15-second claim watcher. A managed-recovery preflight still independently rejects unverified snapshots; it can incorporate later Session reflection edits without adding time spent frozen. If the claim returns to this device, the runtime resumes only when the frozen state was saved and the TimerEngine actually resumes. No guarantee of recovery exists when every browser storage surface is unavailable and the page is terminated; keep the page open and heed the warning. The protected claim is v4 with a correlated v2 local safety latch; the canonical Active Session schema is unchanged.

The visible/eligible Active Session claim watcher keeps its **15-second** cadence and the parallel remote claim/strict local session reads. A confirmed-offline browser avoids futile Drive claim reads; returning online or making a hidden tab visible can immediately perform a missed eligible check. Those event-driven wakes use the same single interval owner's 15-second attempt throttle and the check's existing in-flight guard. Explicit claim verification remains independent of the wake throttle so a failed frozen-session local write can still retry through the normal direct path. This is **open-app cooperative work**, not a closed-app OS background service, and remote handoff cannot be observed while truly offline.

## Handoff safety and recovery

**Critical transfer.** The existing profile-scoped `sessionHandoffSafety` v2 marker is committed before requesting the protected Drive ownership claim v4. It correlates the random handoff token, opaque observed-owner token, exact semantic-content fingerprint, observed/proposed revisions and owner epoch; older marker/claim versions remain readable but cannot falsely pass v2/v4 correlation. The selected Drive head is independently verified under the publication lease, and only a successful strict IndexedDB write/read-back of the new owner session permits execution.

**Uncertain ownership always stops the timer.** On reload, verify the persisted marker, strict canonical local session, newest applicable Drive claim and current remote Active Session. A proved accepted claim may be adopted; a newer demonstrably valid owner may supersede it without resuming a local timer. Compensation uses the repository's existing strict `expectedCanonical` compare-and-write and verifies that the local record still equals the expected predecessor. A concurrent edit, mismatch, unverified remote claim, offline read, lost authority or failed compensation leaves the marker and freezes execution. The recovery verifier is single-flight, idempotent where proven, and must not mutate Plans, Notes or Saved Days merely to claim ownership. The UI exposes Verify ownership; normal auto-resume/restore obeys the marker.

**Date-first recovery.** Once a handoff-safety latch resolves, strictly reload and classify the canonical session date before any Continue Here, Restore Session, suspended-session restoration or timer start. Earlier-day active/suspended sessions—whether this or another device last owned them—are historical Review work, never a current runnable or transferable timer. An already saved, durably acknowledged and fully covered previous-day recovery row can retire after canonical verification. Otherwise recover into Review without starting the clock, preserve for later or deliberately discard only when local ownership and strict deletion permit. If the canonical row changes while a choice is pending, invalidate that stale choice.

**Plan draft remains independent.** Continue Here flushes any pending draft write, waits for the existing canonical writer and compares the nullable stored draft against the displayed text before claiming execution. It reads only the newest verified remote Active Session for handoff, not other Personal Data. Applying that session's schedule uses `persistDraft:false` and leaves the authoring draft intact and the board in LIVE mode unless edit was deliberately opened. Cancel and Done honor editor epoch, in-flight changed text and strict persistence. An untouched default (`draft:null`) must not be manufactured as an authored plan; independently authored drafts may still legitimately reconcile during subsequent Personal Data sync.

## Saved Day evidence and reminders

**Canonical save and acknowledgment.** `review.js` commits a Saved Day through the strict IndexedDB repository and requires exact read-back before announcing success; a localStorage rescue-only result is not a canonical Day. Only the same Active Session lineage may advance and strictly persist `savedRevision` after its own Day is verified. The Day's `sourceRevision`, and another device's `contentRevision`, are not comparable ancestry clocks.

**Shared evidence predicate.** `DailyRecordCodec.savedDayCoversSessionEvidence` checks schedule, task outcomes, focus/time/pause evidence, Review content, adjustments and Practice Pacer. Completed runs match one-to-one. An earlier unfinished active attempt requires an independent matching finalized partial run with the same task/target/plan metadata and a non-decreasing observed unit-duration prefix. A running unit accumulates only through the canonical snapshot timestamp and is capped at **the same 24-hour per-unit maximum as live Practice Pacer**. Unrecorded/shortened work, changed identity, contradictory timestamps and unknown or rescue-only proof remain reviewable; a zero-time practice setup is not study evidence.

**Cross-date reconciliation.** The original last-shared full-record hashes retain their meaning, while the local `ReconciliationBase.v5` stores a distinct Active Session semantic-content hash. Together with the verified Saved Day and protected ownership claim, these can prove one-sided continuation or a completed earlier day. Semantic similarity alone cannot change the execution owner, and cross-device numeric revisions alone cannot authorize deleting a recovery row. An old-owner runtime is quiesced before replacement; any extra study captured at yield remains a retained alternative.

**Reminders are not data receipts.** `savedRecordExistsForDate` and `revalidateSaveReminderAfterCanonicalConvergence` compare the current canonical Day with the originally captured warning evidence, the current live/canonical session where available and any still-open divergent retained session. A failed strict read, rescue-only copy, changed runtime or uncovered alternative keeps the warning. Verified convergence may remove **only** the obsolete warning and its matching inline prompt without writing `savedRevision`, changing stored records or clearing newer feedback. A per-reminder generation prevents an old asynchronous verification from dismissing a newer same-day notice.
