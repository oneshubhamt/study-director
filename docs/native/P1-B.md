# P1.B — native Drive integration intake

Entry runtime: `bdfaf9b6e3df4cac873c64a7ea3c5885cdec8462`; P1.A qualified before implementation. This is a design and acceptance specification, not completed implementation.

## Actual source audit

- `source/external/drive.js` owns GIS/drive.file grant, per-profile localStorage bearer, request timeout/abort and retry classification, validated HTTPS endpoints, folder/profile/deletion markers, publication and maintenance leases, canonical object/commit transport, multipart ≤5 MiB and 2 MiB resumable chunks, bounded ranged reads ≤1 MiB and streaming full reads. The core `backup-provider.js` owns foreground/background coordination, convergence/reconciliation, safety/retention, journal and UI status. Keep both engines; split the actual auth/transport seam rather than copy the provider.
- `findFolder` rejects incomplete/ambiguous/unsafe listing, but `resolveFolder` creates when none found. A narrow native grant can return a complete *visible* subset, not global absence. Do not allow native creation from this result. Existing stored folder ID is also authoritative evidence: refuse missing/different marker, account, folder or profile rather than creating another. Initial native enrollment must prove access to an existing PWA repository and its commit/object bytes before mutation. A new native-only library is a later explicit policy decision after interoperability, not implicit fallback.
- `connectProvider` calls prepare/authorize/verifyAccount then wakes existing scheduler. `bindDriveLibrary` records account/folder and may adopt a portable profile ID; `profiles.js` preserves a stable local scope while adoption changes portable ID. Bind native credential/connection epoch to stable scope plus verified account, fence every operation against original identity; do not use mutable portable profile ID as credential storage key. Verify ownership/profile after awaits and before irreversible mutation; stale auth callback, wrong account, cancelled join or disconnect cannot bind/clear successor. Verify known folder before background publication; refuse unknown or changed binding. No tokens or refresh grants in JS. 
- Native shell currently omits GIS bundle, disables all Drive controls with `PlatformRuntime.webDrive`, rejects external navigation/new windows, has no IPC commands and CSP connect-src self. Host native auth is a specific system-browser launch, not remote WebView navigation. Admit provider availability only when actual configured native port is ready; keep PWA GIS/first-start behavior and native unconfigured local-only refusal. Update deployment-contract and native smoke to assert deliberate narrow permissions, not generic IPC absence after integration.
- Transport inventory: GET files list/item/about; POST files metadata/resumable/multipart; PATCH only repository folder rename/trash; DELETE only verified repository objects/coordination markers; PUT validated resumable session status/chunks; GET alt=media. Native transport validates actual operation, fixed HTTPS host/path/method/query and allowed headers, denies redirects, foreign IDs/scope/unverified requests, no generic HTTP/token/shell bridge. Keep shared provider's verification, SHA-256 readback, expected revisions, and original operation checks. Prefer native opaque request handles and bounded chunks/response headers; never buffer entire unbounded media in IPC. Cancel on abort, release on timeout/profile change, cap concurrent in-flight operations; do not retry ambiguous writes at transport layer. Keep one logical repository identity and one scheduler.
- Official [desktop OAuth](https://developers.google.com/identity/protocols/oauth2/native-app) supports system browser, PKCE and loopback; [Drive scope](https://developers.google.com/workspace/drive/api/guides/api-specific-auth) grants per-file visibility, [appProperties](https://developers.google.com/workspace/drive/api/reference/rest/v3/files) private to requesting app. Same Google Cloud project/client visibility must be proven, not assumed. Use desktop client credentials supplied outside Git in approved configuration; no Web client secret or production account. 

## Numbered implementation outcomes

1. **Auth and session boundary:** split web/native auth ports with common provider; native PKCE S256, high-entropy verifier/state, loopback 127.0.0.1 ephemeral listener with strict bounded HTTP callback parsing, state and single-use, timeout/cancel, system browser and fixed Google endpoints, strict exact drive.file, verified account, native credential storage (Windows OS-protected) with stable profile scope and account/client identity; serialized refresh, expiry skew, revoked grant, disconnect local only. Never expose/log tokens, authorization code, refresh or credential config. Unconfigured native must remain local-only. Unit witnesses wrong/duplicate state, expired/cancelled generation, invalid scope/token, wrong account, missing/revoked grant, late refresh after disconnect, offline.
2. **Authorized transport:** native fixed Drive operations (not generic HTTP), typed IPC admitted only packaged main WebView and bounded authorized scope. Narrow request/response metadata, fixed permitted methods/headers, TLS verification/no redirects, limits and cancellation, scoped opaque upload/read handles; no arbitrary file/path/URL. Preserve shared upload status/resume/range/digest/response semantics including 308, 401, 403, 429 and errors after committed mutation. Native refresh can reauthenticate read or next operation; never blindly replay POST/DELETE. Test malformed path/query/headers, foreign scope/object, response overflow, timeout/cancel, redirects, stale handle/generation, partial and ambiguous transfer, exact bytes/checksum. Existing web tests must pass.
3. **Actual integration and discovery:** native provider shares canonical JS repository and backup-controller wiring, UI/startup/background status; native provider registration depends on configured host, secure credential restoration without blocking local boot, explicit connect/choice. Read-only discovery must prove same private PWA folder/account/profile and complete verified inventory, known folder and commit/object witnesses before mutation; no creation on absence; refusal must not erase local data or bind another profile. Profile switching, late callback and failed read/verification fenced. Tests for empty/ambiguous/foreign/incomplete, marker and binding mismatches, user refusal, same folder identity and existing publication/maintenance coordination, non-native regression.
4. **Qualification:** targeted `drive-security`, `drive-profile-binding`, `drive-repository-scale`, automatic-provider, repository/reconciliation/handoff and relevant integration/architecture/build tests, plus existing Drive sign-in/sync-and-profiles/cold-start browser journeys. Native unit and packaged tests for unconfigured/local offline and hermetic protocol/failure witnesses, five clean samples for changed journeys. Actual authorized disposable PWA publishes → Windows discovers same folder and appProperties, reads verified commits/bytes → native publishes under same identities → PWA reconciles; reverse, conflict/deletion/attachment/claim, refresh/restart/cancel/wrong account. External config and consent needed for real test; no live study library. Do not count mocked success as real two-way evidence.

## Dependency decisions

Reuse compatible locked crates and OS APIs where they simplify implementation; review actual supported features and dependency closure before adding. Prefer maintained cryptographic/TLS/URL/HTTP and OS credential APIs over hand-rolled cryptography, broad Tauri plugins or unnecessary storage stack. No fake lockfile. Update native QA to Node 26.13.1 LTS and pin Rust 1.100.0 (verified P1.A runner version); check all affected source/build/runtime paths. Do not modify shared production workflows without authorization. 

## B.1 checkpoint boundary

The shared provider and web connection are separate authored sources (assembled as the one web Drive asset). The common provider selects its connection at composition, admits native writes only after existing verified bytes and binding, and retains original auth identity on operations/cleanup. Hermetic tests inject a tokenless native host contract into the real provider; they are not a native host implementation or live Drive evidence. B.2 must implement and wire the narrow OS credential/OAuth/HTTP boundary and independently enforce scope/operation limits, then test actual native calls. The native shell remains unavailable for Drive until configured and qualified. B.2 must distinguish authorized account from admitted repository in restored connection and status/background scheduling; a failed native proof cannot report a usable backup location.

Native admission additionally checks deletion status for the remote portable profile before binding and again after the awaited decision, before admitting mutation. A still-visible folder does not supersede a deletion marker. Unknown or incomplete deletion-status listings fail closed; refusal of an unadopted remote profile must not notify local profile deletion. The common provider still cannot prove global visibility under a per-file grant; real disposable-account qualification remains mandatory.
