### Reproducible observations

- **The production data gap is real.** Used the production codec factory and the factory wiring in each branch's `tests/integration/backup/current-canonical-roundtrip.mjs`. Serialized F33's canonical suspended-session sample to JSON, then passed the very same JSON to both `sanitizeCurrent` implementations. F33 accepted it. The pinned TS application rejected it. The Phase 8 upgrade needs a full F33 in-place and external-copy rehearsal beyond this record-level reproduction.
- **Closing the app after a verified restore can reverse the result on TS.** Invoked each production `recoverInterruptedRestore()` with the same controlled journal and recorded its calls. With a writable `verified` journal, F33 rebuilt preparation state, cleared the journal and kept the incoming data. TS called `rollbackImportedState` with the safety copy and cleared the journal. With an earlier phase both invoked rollback. With a verified journal on a secondary tab both deferred without writing. The TS restore and sync writers do mark journals verified. This is an acceptance blocker for P8.1. Repeat it on actual stored records with a process restart.
- **The Notes identity contract differs.** Invoked the daily-record codecs on both branches. F33 exposes `noteKeys.support` with fixed ID `n_f0929787c2c33fc9`, label `Support Activities` and normalized title `support activities`. The TS codec exposes generic ID operations and no such binding. Exercise the complete editor → repository → second-device identity path.
- **Markdown contains both a confirmed gap and equivalent cases.** Bundled each real `rich-text/markdown.ts` entry with esbuild. For two lines starting with `• `, F33's detector returned true and its renderer produced a two-item list. TS returned false and produced a paragraph with a line break. A nested hyphen list, a numbered list and plain prose produced identical detector results and HTML on both branches. These observations cover the pure reader. The final acceptance test must also paste into the mounted editor, undo and reload.
- **Drive has a consequential side effect difference.** F33's `source/external/drive.js` supplies the saved account as `login_hint`, checks the authenticated account before repository access and clears the local session on Disconnect. TS's `source/external/drive.ts` calls OAuth `revoke` on Disconnect and lacks the equivalent account-hint/check path. Ran F33's built Chromium `tests/browser/backup/drive-sign-in-again.mjs` with the simulated provider. It passed all nine checks, including wrong-account refusal, one-tap after reload, pending upload, profile Sync now and disconnect during sync. TS's own `drive-security.mjs` passed its separate security assertions. Both contracts belong in SDVC1.
- **Targeted reference evidence.** F33's `previous-day-question.mjs`, `note-catalogue.mjs` and `support-note-identity.mjs` passed against their production functions. On the built F33 app, Chromium also passed `reflection-through-sync` (unopened Review, previously opened Review and phone-to-laptop typing) and `rollover-saved-day` (ten sleeping/awake, saved/unsaved and cross-device cases). TS's `tests/integration/backup/capture-safety.mjs` and `tests/integration/app/ownership-hydration-fail-closed.mjs` also passed. These tests use controlled stores, clocks or ports. They establish reference expectations for P8.0. No physical device, live provider or production upgrade was used in this intake.

F33's `docs/backlog.md` still records the phone/iPad cold-start disappearance of local data as a top-priority incident. The census and out-of-database record give evidence after a loss. A simulated deletion confirms the instrumentation, while the cause of the field incident remains unverified. Carry the outstanding report, owner-only recovery and device checks into the release assessment.

A separate naming experiment changed only the release string in a disposable copy of the typed tree. An archive without Git provenance was rejected by Firebase staging. After recording the experiment in its own temporary Git commit, `npm run build`, `npm run verify`, `npm run stage:firebase:minified` and `npm run test:release:minified` passed with `SDVC1` and derived release ID `vc1`. No release-parser change was indicated. These bytes came from the pre-parity application and have no release standing.
