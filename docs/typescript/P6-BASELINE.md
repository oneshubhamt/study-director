The workflow definitions and test IDs are pinned by the application SHA.

The TSV covers all 291 tracked paths in tests, 18 in build, seven in contracts, 11 workflows and 13 root tooling/configuration paths. It assigns an environment, baseline selector, type-check status and primary pass to every path. The pass is a starting assignment; move a caller, fixture or helper with the operation it verifies. Browser fixtures also cross the Node/page/worker boundary. Check the embedded browser code and its actual runtime inputs when converting the harness.

Four native Python/shell/Windows entries, 11 workflows, 12 configuration files and two documentation files have explicit dispositions. The fixture directory contains guidance only. Actual generated inputs and fake storage/providers live in test bodies and helpers.
- The scope table excludes the already inventoried application, generated bundles, vendor sources and application type/declaration trees. The five compiler projects still own their admitted inputs, including the Node type witness. Preserve the negative type and vendor declaration checks. The Node admission set is directly inspectable in `tsconfig.node.json`; an executable file accepted by discovery can still be outside it.
- Compared the production selectors with every tracked file in the four executable test directories. Unit 32 + integration 105 + architecture 33 = 170 fast; 12 separately selected release files; 59 browser files (13 smoke, 36 feature, 10 extended). No overlaps or missing files. Ten browser scenarios specify `alone`; quarantine is empty. The `source-reader` flag identifies direct use of the named source helpers or the helpers themselves. Direct FS reads, snippet slicing and browser strings also require caller inspection. A reader flag alone gives no grounds for deletion.
- Keep the 14 per-module line/block/function floors and ten critical path checks visible until their successors are proved. The fast coverage reporter considers 132 production sources; 93 were observed, 39 have explicit non-fast owners. Aggregate percentages use observed files. The separate AST-edge reporter scans a different set of roots and uses a different denominator.

## Measurement and priorities


One local Linux x64 runner exposed two CPUs (quota 2), Chromium 156.0.8078.79. Fast and coverage used two child processes. The measurements below are wall time. Dependencies were installed and filesystem caches were uncontrolled. Each browser case created fresh profiles; cold and retained openings *within* the Insights test are separate measurements. The first build shared the pinned dependencies through a symlink; esbuild changed two generated source-path comments. A second build with dependencies installed at their normal location passed verification and reproduced the tracked generated files byte-for-byte. Use the normal layout for artifact hash comparisons.
