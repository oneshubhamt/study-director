# Phase 7 · Certify the converted application

**Planned after Phase 6.** Deliver a verified typed baseline for the [Phase 8 F33 comparison](PHASE-8.md). The reason for a separate certification phase is that a feature can pass in isolation while the packaged app loads a different worker, loses a write across restart or behaves differently on a device. Certification covers the composed application, its shipped artifacts and the environments named in the programme.

Use the [verification procedure](../VERIFICATION.md), [browser reliability rules](../../tests/README.md) and [shared executor guidance](../../AGENTS.md#executor-judgment-across-phases). These activities may share a run or be ordered around dependencies and device availability. Each required claim needs an observable result.

| Activity | Executor action and evidence |
| --- | --- |
| Establish the candidate | Pin the Phase 6 exit SHA, lockfile, tool versions, source and generated inventory. Read the execution record for outstanding limits and prior failures. Map the supported paths, risks and device obligations to actual checks. Give each an owner and an expected result. Build a clean candidate and identify the exact artifact used for browser/device work. |
| Reconcile behavior and automation | Trace normal entry points through the typed owners into the build. Include startup/profile isolation, Plan and timer, Review/Diary, Notes and attachments, backup/restore, handoff, Insights, presentations, plugins and PWA update. Exercise critical adjacent flows and observable persisted state. Run the Phase 6 successor to the full promotion chain. Inspect actual hosted jobs, selections, coverage, mutation, performance and release results. Today the hosted browser input is opt-in. Confirm every required tier actually ran. |
| Exercise environment-sensitive risks | Use disposable profiles and designated test repositories. Exercise installed physical iOS/Safari, offline reopen and update, storage interruption/recovery, and live Drive authorization and transfer. Compare the records and attachment bytes after restart. Exercise the maximum-import journey and isolated Insights performance at the documented capacity and budget. Use representative keyboard, focus and mobile interaction checks where those are part of the journey. Record OS, browser, inputs, build and results. If hardware or access is unavailable, keep that claim open while independent checks proceed. |
| Repair, recheck and hand off | Preserve reproductions and decide whether the app, test or environment caused each failure. Fix the actual owner, run the focused regression, then certify the final candidate. Reuse results whose inputs and affected execution paths remain identical with a recorded justification. Rebuild and rerun affected evidence after any change. Record the certified SHA and artifact manifest/digests, commands and run links, manual results, material limitations and a clear gate decision in the existing execution record. Preserve a runnable reference for P8.0. |

Keep F33 product differences in the Phase 8 ledger. A Phase 5/6 regression discovered here belongs to the typed candidate. An unresolved mandatory check leaves Phase 7 open. Distribution and SDVC1 packaging belong to the later release process.

**First executor command after Phase 6:** Start Phase 7 on ts-exp. Pin the Phase 6 exit SHA, reconcile outstanding certification obligations against the actual suite and device matrix, build the reference candidate, and record coverage and open checks. Follow the current authorized pass boundary.
