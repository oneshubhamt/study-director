### Design philosophy inferred from the *production source*

**CLEER = Clean, Lean, Efficient, Elegant, Robust and Reliable** (R includes both *robust* and *reliable*). A fix is complete only when the app operates as one coherent system, not a collection of special cases. The source exhibits these principles:

- **Local-first, user-directed study.** The user authors the Plan; its independent working draft is not the Active Session's applied schedule. Execute/Review/Saved Days capture actual study evidence. A handoff must change *execution ownership*, not silently edit unrelated personal data (`source/core/plan.js`, `review.js`, `source/app.html`).
- **One authority per datum and transition.** Canonical structured records live in IndexedDB; OPFS holds attachments; browser-storage recovery is an emergency aid, not a committed Active Session. Runtime controls are projections of canonical state, not authorities (`repositories.js`, `ownership.js`, `session-lifecycle.js`).
- **Optional, verified synchronization.** Drive is a coordination/backup provider, never required for local studying. A write/claim/checkpoint must be verified; unknown is not absent, and a failed transaction cannot silently imply success. Device Folder shares repository semantics without being a second sync channel (`backup-provider.js`, `managed-repository.js`, `backup.js`).
- **Distinct failure domains, narrow contracts.** Frozen internal module ports, an explicit mutation owner, strict critical writes, reusable transaction/recovery primitives, and narrow side effects. Reuse those contracts rather than adding another save queue, special-case router, shadow source of truth or generic orchestration framework (`internal.js`, `mutation-coordinator.js`, `save-lane.js`).
- **Causal correctness before clocks or convenience.** Neither a numeric revision from another device nor a global checkpoint timestamp establishes that particular content was saved or that one setting supersedes another (`record-codecs.js`, `reconciliation-baseline.js`, `backup.js`).

**Topology/architecture freeze:** Do **not** add IndexedDB stores, OPFS entities, browser-storage keys, backup format fields, persisted schema fields/versions, compatibility machinery, new source-of-truth copies, or a new subsystem as part of this programme without **first showing the precise need, lower-impact alternatives, data-safety implications and proposed minimal contract to the owner, then waiting for explicit approval**. Prefer existing canonical data and existing provenance. A small internal function refactor is allowed only when it reduces competing logic; preserve the established subsystem boundaries. Never force a “successful” automatic merge without enough causal evidence. Do not rewrite migration/history data or change repository/deployment topology casually. No unnecessary abstractions, duplicate rules, speculative performance optimization, or unrelated UI work.

**Invariants common to every pass**

1. A → B → A ownership transfer cannot start two live clocks, silently revert the latest claim, corrupt study evidence, or touch an unrelated Plan draft merely to change ownership.
2. “Applied schedule”, “independent draft”, “editor open”, “canonical Active Session”, and “Saved Day” are five separate facts. A zero-task screen or absent draft is not proof that the user entered edit mode. A draft that was never explicitly saved is not automatically equal to the displayed default template.
3. Saved means **the identified study content** was committed as a canonical Saved Day, not merely that a record exists for that date or that revision numbers match. An unsaved divergent branch is retained, never silently retired. Repeated obsolete unsaved-day notices stop after authoritative convergence.
4. Identical semantic data creates no new review. Unrelated independent changes merge only with proven ancestry; true divergence remains accessible and understandable. Never invent device identity, timestamps or conflict causes where they are not recorded.
5. Failed, interrupted and resumed transitions have explicit, recoverable outcomes: *verified complete*, *verified compensated* or *blocked with actionable durable recovery*. A “best-effort” return value cannot be mistaken for durable success.
6. Do not sacrifice ordinary offline study, tablet/desktop use, notes/attachments, user data, backup safety, privacy or accessibility to fix these bugs.

It is an explicitly *partial* remedy, not BF-1R3 closure.

**Minimal persistence design (approved and implemented):**

- Reuse the **existing profile-scoped `sessionHandoffSafety` key**; advance its value to v2 with opaque `handoffToken` (random per attempt), observed owner token, exact observed revision/content fingerprint, and proposed revision, retaining date, checkpoint ID, installation and creation time. Existing v3 claims remain readable, but v3/v1 claims without the token cannot be falsely certified as that v2 attempt. Reuse the existing verified claim upload/read-back, publication lease, strict IndexedDB save/read-back and exact release mechanisms; compensation carries the same token and its higher epoch.

It may (1) adopt verified ownership with strict canonical read-back; (2) verify precise compensation; or (3) remain blocked without altering either side, preserving divergent work. Do not start a timer on uncertainty. Add replay-safe tests for failure after each stage, claim supersession, changed source, lost IndexedDB writes, offline/reload and compensation failure.

**Tradeoff:** a marker-only v2 without a matching claim token stores more source evidence locally but cannot conclusively correlate a claim that was published before the app could record its epoch. One matching opaque token in both existing records is the minimal cross-failure-domain link; it does not expose study content. The provider's existing claim format needs a narrowly versioned parser/writer change, not a new storage topology.
